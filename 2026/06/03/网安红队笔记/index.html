网安红队笔记

红队打点思路

一、快速漏洞扫描

  1. 核心工具
  • fscan：全端口扫描、弱口令爆破、漏洞探测、内网存活主机识别，轻量一键扫描，适配内外网快速打点
  • Nuclei（nulei 为拼写误差）：基于 POC 模板引擎，自定义漏洞库，速度快、更新频繁，支持批量批量 URL 批量检测
  • Afrog：高性能漏洞扫描器，集成各类 Web 漏洞、中间件漏洞，资源占用低，输出结果直观
  1. 专业术语释义
  • POC（Proof of Concept，概念验证）：仅验证漏洞是否存在，无破坏、无提权、无数据窃取，只证明漏洞可被触发
  • EXP（Exploit，漏洞利用程序）：在 POC 基础上实现漏洞利用，可执行命令、写入木马、获取服务器权限、读取敏感数据
  • Poc：漏洞验证脚本
  • exp：漏洞利用脚本

  1. 配套操作流程

    资产收集→端口服务探测→匹配对应 POC 批量扫→高危漏洞用 EXP 尝试拿权限→输出扫描报告标记风险等级

二、手工渗透

  1. 信息搜集

    域名备案、子域名爆破、DNS 解析、目录扫描、robots.txt、JS 接口扒取、CMS 版本、中间件（Nginx/Apache/Tomcat）指纹识别

  2. Web 层漏洞手工测试

    SQL 注入、XSS 跨站、文件上传、文件包含、SSRF、命令执行、权限越权、未授权访问、逻辑漏洞（验证码复用、密码重置缺陷）

  3. 权限提升

    Webshell 连接、服务器本地提权（Windows 内核漏洞、Linux 脏牛 / Sudo 权限滥用）、数据库提权

  4. 内网横向移动

    抓取凭证（Mimikatz、浏览器密码、数据库账号）、SMB 爆破、RDP 暴力破解、代理隧道（Frp/Socks）渗透其他主机

  5. 痕迹清理

    删除操作日志、清理临时文件、清除 Web 访问日志，规避溯源

三、钓鱼攻击

  1. 钓鱼类型
  • 邮件钓鱼：仿官方企业邮箱，附带恶意附件（宏 Excel、木马压缩包）、伪造登录跳转链接
  • 仿站钓鱼：复刻后台、OA、网盘、支付登录页，窃取账号密码、验证码
  • 社交钓鱼：微信 / QQ / 企业微信伪装同事运维，发送恶意工具、诱导执行脚本
  • 短信钓鱼：伪装运营商、银行、平台，诱导点击恶意链接下载 APK 木马

  1. 载荷手段

    捆绑木马程序、恶意宏文件、远控后门、窃取证书工具；移动端植入盗号 APK

  2. 配套欺骗手段

    伪造域名（形近域名、 punycode 编码混淆）、伪造证书、仿官方 LOGO 文案降低警惕

四、供应链攻击

  1. 攻击逻辑

    不直接攻击目标企业，转而入侵其上下游依赖组件、第三方服务商、开源依赖库

  2. 常见攻击面

  • 开源组件投毒：篡改 Maven/NPM/PyPI 仓库内依赖包，植入后门代码，企业打包部署后自动中毒
  • 第三方软件植入：入侵开发工具、运维插件、杀毒辅助程序、OA 插件
  • 服务商沦陷：攻破云服务商、CDN、外包运维平台，批量劫持下游客户业务

  1. 典型危害

    批量控制数千企业服务器、静默持久后门、批量窃取业务数据，隐蔽性极强，常规扫描难以发现

五、近源渗透

  1. 攻击场景：物理近距离接触目标网络环境
  2. 攻击方式
  • WiFi 渗透：抓包破解 WPA2/WPA3 密码、钓鱼 WiFi 热点（同名伪 AP）、无线中继劫持流量
  • 物理接口渗透：机房 USB 口插 BadUSB/U 盘木马、网口直插内网，接入局域网横向扫描
  • 蓝牙 / NFC 攻击：抓取蓝牙设备凭证、NFC 标签篡改

  1. 拓展操作

    接入内网后对内网打印机、监控、工控设备、办公主机批量弱口令爆破；搭建内网代理突破边界防护

网络安全的渗透流程

标准渗透测试完整流程

  1. 前期授权与范围确认

    签订书面渗透授权书，划定测试 IP、域名、业务系统、测试时间，明确禁止操作范围（数据库核心、生产业务、用户隐私数据等），规避法律风险。

  2. 公开信息侦察（被动信息搜集）

    不触碰目标服务器，利用公开平台采集资产：备案信息、子域名、DNS 记录、历史解析、Github 泄露源码、招聘运维信息、企业社交平台、网盘泄露文件、Whois 信息、AS 网段、第三方测绘平台资产。

  3. 主动信息探测（主动侦察）

    主动发包扫描目标：存活主机探测、端口扫描、服务版本指纹识别、操作系统识别、中间件（Nginx/Tomcat/Apache）、CMS 类型、脚本语言、数据库类型、路由防火墙设备识别。

  4. 目录与路径侦察

    扫描后台地址、管理路径、备份文件、配置文件、日志文件、上传目录、robots.txt、js 接口、API 路由、测试页面、探针页面。

  5. 弱口令与账号爆破

    针对登录入口、数据库、远程服务进行爆破：后台账号密码、FTP、SSH、RDP、MySQL、Redis、MSSQL、SMB、路由器管理口；工具批量字典爆破、验证码暴力撞库。

  6. 漏洞手工 + 工具扫描验证

    使用 fscan、Nuclei、Afrog 批量扫描 POC，同时手工检测主流漏洞：SQL 注入、XSS、文件上传、文件包含、SSRF、命令执行、未授权访问、越权、逻辑漏洞、中间件 CVE 漏洞。

  7. 漏洞利用（EXP 执行）

    对验证可利用的漏洞加载 EXP 程序，触发漏洞实现交互访问、命令执行、文件读写等操作，区别于仅探测存在的 POC。

  8. 初步权限获取

    通过漏洞利用拿到基础权限：Webshell 网站权限、数据库操作权限、普通系统账户、只读访问权限等低级别权限。

  9. 本地权限提升（提权）

    低权限账号升级至高权限管理员：

    Windows：内核漏洞提权、服务配置漏洞、计划任务、注册表、第三方软件漏洞；

    Linux：Sudo 权限滥用、SUID 程序、内核漏洞、定时任务、环境变量劫持。

  10. 凭证抓取与信息窃取

    抓取主机内敏感数据：系统账号哈希、浏览器密码、数据库连接账号、Redis/Mongo 凭证、远程登录密钥、运维配置文件、内网网段清单。

  11. 内网横向移动

    以拿下的主机为跳板渗透内网其他设备：SMB 爆破、IPC 连接、RDP 远程登录、SSH 密钥复用、WMI 远程执行、票据传递攻击。

  12. 持久化后门驻留

    建立长期可控通道：添加隐藏管理员账号、创建计划任务后门、写入 Web 一句话木马、注册表自启动、服务后门、内存马、端口转发后门。

  13. 隧道代理与边界突破

    搭建代理、端口转发、FRP/SOCKS 隧道，穿透防火墙，访问隔离网段、内网后台、数据库服务器。

  14. 核心资产深度渗透

    攻击核心设备：域控服务器、数据库集群、存储服务器、监控、工控、OA、财务系统，获取核心业务数据。

  15. 痕迹清理

    清除系统日志、Web 访问日志、操作临时文件、命令历史记录、上传木马文件、删除新建账号与计划任务，消除入侵痕迹。

  16. 输出渗透测试报告

    整理漏洞详情、风险等级、复现步骤、危害影响、针对性修复方案、加固建议，交付甲方整改。

CMS 完整学习体系 + 渗透信息搜集环节细化

一、CMS 整体四大学习模块

1. CMS 架构解析、CMS 环境部署

  1. CMS 基础架构
  • 三层架构：前端展示层、后台业务逻辑层、数据存储层；
  • 运行依赖：Web 服务 (Nginx/Apache)+ 解析语言 (PHP/Java/.NET/Python)+ 数据库 (Mysql/Mssql/PostgreSQL)；
  • 文件结构：模板目录、插件目录、上传目录、配置文件、后台管理目录、缓存目录；
  • 主流分类：PHP 型 (织梦 DedeCMS、帝国 ECMS、ThinkPHP 框架 CMS、WordPress、Discuz)、Java 型 (JFinal CMS、JEECG)、.NET 型 (动易 SiteFactory)。
  1. 本地环境部署
  • PHP 集成环境：phpStudy、XAMPP、LNMP、宝塔面板；
  • 部署步骤：下载 CMS 源码→创建数据库→导入 sql 备份文件→访问安装页面填写数据库账号→后台初始化配置→绑定域名；
  • 多版本切换、伪静态配置、文件权限配置、HTTPS 证书部署、插件手动安装与卸载。

2. CMS 漏洞挖掘、测试及综合利用

  1. 漏洞挖掘途径
  • 公开 CVE 漏洞库匹配对应 CMS 版本；
  • 第三方漏洞平台历史漏洞复盘；
  • 黑盒测试主动发包探测；
  • 插件、主题模板漏洞（CMS80% 高危漏洞出自第三方插件）。

  1. 常见 CMS 高频漏洞类型

    SQL 注入、文件上传、远程代码执行、文件包含、XSS 跨站、后台弱口令、未授权访问、越权访问、变量覆盖、命令执行、逻辑漏洞（重置密码、支付篡改）。

  2. 综合利用思路

    弱口令进后台→上传木马拿 Webshell→服务器提权→内网横向；

    插件漏洞直接 EXP 一键拿权限；

    注入漏洞脱库获取管理员账号密码登录后台。

3. CMS 源码静态审计、动态调试、漏洞修复和加固

  1. 静态源码审计

    通读核心功能代码（登录、上传、数据库查询、文件操作）；审计过滤函数是否失效、可控参数是否过滤、全局配置缺陷；查找危险函数（eval、file_put_contents、system、exec 等）；审计过滤白名单 / 黑名单逻辑缺陷。

  2. 动态调试

    PHP：Xdebug 断点调试、抓包对比传入参数与后台处理逻辑；Java：IDEA 断点调试；跟踪参数从前端传入→控制器处理→数据库交互完整链路。

  3. 漏洞修复

    对存在缺陷代码改写过滤逻辑；升级 CMS 官方补丁版本；禁用危险函数；修复文件权限、路径过滤。

  4. 安全加固

    修改后台默认路径；限制后台 IP 访问；复杂密码 + 双因素认证；关闭文件写入权限；定期更新内核与插件；禁止暴露版本号；开启 WAF 防护；限制上传文件类型与大小。

4. 渗透测试报告编写

  1. 报告基础板块：授权说明、测试范围、测试时间、资产清单；
  2. 漏洞详情板块：漏洞地址、漏洞类型、风险等级、复现步骤、POC / 截图、危害描述；
  3. 汇总板块：整体风险评估、漏洞数量分级统计；
  4. 整改板块：分点给出精准修复、加固方案；
  5. 结尾附录：工具清单、日志、原始扫描数据。

二、渗透第一步：信息收集（渗透耗时占比 80%）

1. 域名基础信息收集

  1. Whois 信息：注册人、电话、邮箱、注册商、过期时间、备案主体；
  2. 工信部备案信息：确认企业主体、核验业务归属；
  3. DNS 解析记录：A 记录、CNAME、MX、NS 记录，挖掘备用服务器、邮件服务器；
  4. 历史解析记录：查询过期旧 IP、废弃子域名（高危遗留资产）；
  5. 第三方平台：爱站、站长工具、天眼查挖掘企业关联业务、其他站点。

2. 子域名全面搜集

  • 工具：subfinder、Sublist3r、oneforall；

  • 字典爆破 + 接口查询结合，挖掘后台、测试、api、admin、mail、dev 等高危子域名；

    子域名常存在低版本 CMS、未加固测试站点，极易突破。

3. 端口信息收集

  1. 核心扫描工具：Nmap

    基础扫描命令示例：

plaintext

  1. 重点关注 Web 端口：80 (HTTP)、443 (HTTPS)；

    附带高危拓展端口：8080、8090、81、8443、7001、9000 等（多为后台、中间件管理页面）；

  2. 扫描输出内容：开放端口、运行服务、服务版本、操作系统识别。例：（端口的信息收集80、443web的端口）发现是web，做cms的指纹识别

4. 服务版本 & 端口指纹识别

  1. Nmap 自带指纹库识别 Apache、Nginx、Tomcat、MySQL、Redis、FTP、SSH 等服务版本；
  2. Web 指纹即 CMS 标识：页面源码注释、底部版权、请求头、cookie 特征、特定路径文件（如 /feed.php、wp-config.php 专属文件）判断 CMS 类型；

5. CMS 指纹识别专用工具

  1. 通用指纹工具：WhatWeb

    识别 CMS、中间件、脚本语言、插件、服务器版本、开启模块；批量扫描多站点指纹。

  2. WordPress 专属工具：Wpscan

    专门扫描 WP 版本、已安装插件漏洞、主题漏洞、暴力枚举管理员账号、内置 WP 专属 POC 检测。

  3. 其他辅助：cmsIdentify、Eyewitness、潮汐指纹平台。

6. 目录爆破（dirsearch 为主力工具）

  1. 爆破目标：后台地址、备份压缩包 (.zip/.bak/.sql)、配置文件、探针、上传目录、日志、测试页面；
  2. 常用字典：后台大字典、备份文件字典、API 路径字典；
  3. 补充工具：dirmap、ffuf（高速 FUZZ 爆破，支持参数匹配状态码 / 长度）。

7. 易爆出漏洞的重点探测点位（补充）

  1. JS 接口
  • 网页内 JS、axios/fetch 请求接口、api.js、admin.js、路由 JS 文件；
  • 风险点：接口未鉴权、越权查询数据、参数可控导致注入 / 命令执行、泄露后台路径与密钥、明文账号密码；
  1. 小程序
  • 抓包小程序 HTTPS 请求域名与 API 接口；反编译小程序 wxss/js 源码；
  • 风险点：小程序后端接口无权限校验、支付逻辑漏洞、用户信息越权读取、硬编码密钥、上传接口无过滤；
  1. 其他补充高危点位
  • 静态资源：.env 配置文件、git 泄露 (.git 文件夹)、svn 源码泄露；
  • 移动端 H5 站点、APP 后端接口；
  • 插件独立访问地址、模板独立页面。

打红队时的一些额外的知识技巧

一、网络边界含义

网络边界是不同安全等级网络区域之间的隔离分界线，用来划分信任程度不同的网络环境，依靠硬件、策略做访问管控。

  1. 常见边界类型
  • 外网与企业内网边界：互联网 ↔ 办公内网，中间部署防火墙、WAF、路由器、负载均衡；
  • 内网分段边界：办公区 ↔ 服务器区 ↔ 核心数据库 / 域控区，用防火墙、ACL、网闸隔离；
  • 云边界：公有云外网、VPC 私有子网、云服务器之间安全组边界；
  • 物理边界：机房内网、WiFi 无线网络、访客网络、工控专网之间隔离；

  1. 边界防护作用

    默认阻断外网主动向内网发起连接，只放行业务所需端口（80、443 等），拦截扫描、攻击流量；边界是第一道安全防线，一旦边界被突破，攻击者就能向内网横向渗透。

二、寻找程序框架 + 匹配历史漏洞

  1. 识别框架 / 中间件 / CMS

  • 指纹识别：响应头、页面底部版权、专属文件路径、Cookie 特征、静态资源文件名判断；

    例：ThinkPHP、Spring、Struts2、DedeCMS、WordPress、Flask/Django、Tomcat、Nexus、Shiro；

  • 工具辅助：whatweb、nmap、wpscan、fscan、Nuclei 指纹库批量识别；

  • 源码 / JS 溯源：读取 js、配置文件、报错页面，暴露框架版本号。

  1. 匹配对应历史漏洞

    1）拿到精确版本号后，去 CVE 官网、CNVD、漏洞平台搜索该框架版本对应的公开漏洞；

    2）常见高危漏洞类型：远程代码执行 RCE、SQL 注入、文件上传、文件包含、未授权访问、反序列化；

    3）调用 Nuclei、EXP 工具，用对应 POC 先验证漏洞是否真实存在，确认可利用再深度操作；

    举例：ThinkPHP5.0.23 存在 RCE、Shiro 存在反序列化、Struts2 系列远程命令执行。

三、漏洞利用后上传 Webshell 持久控制（拿下 Flag 思路）

  1. 漏洞验证成功、获得文件写入 / 命令执行权限后，优先上传一句话 Webshell；
  2. 上传时机逻辑
  • 哪怕管理员后续修复本次漏洞（打补丁、改参数过滤、升级框架），只要 Webshell 文件未被删除、Web 服务正常运行，依旧可以直接连接拿到站点权限；
  • 属于持久化后门，规避单次漏洞修复导致权限丢失；
  1. Webshell 上传方式
  • 文件上传漏洞：直接提交.php/.asp/.jsp 木马文件；
  • 命令执行漏洞：echo、file_put_contents、重定向写入脚本文件；
  • 文件包含 / 解析漏洞：配合图片马 + 解析漏洞运行脚本；

  1. 后续操作

    1）蚁剑 / 菜刀连接 Webshell，获取网站文件读写、系统命令执行权限；

    2）读取网站配置文件（数据库账号密码、后台密钥、内网地址）；

    3）本地提权、抓取凭证、内网横向移动；

    4）读取目标存放的 Flag 文件（靶机竞赛场景）、窃取业务数据；

  2. 持久化加固后门（进阶）

    除普通 Webshell 外，可叠加隐藏后门：内存马、隐藏账号、计划任务自启动、修改网站模板植入隐形脚本，大幅降低被查杀清理概率。
