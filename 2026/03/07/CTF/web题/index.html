信息泄露

log

  • git 泄露
  • 查看历史记录
  • 切换版本
  • 对比两次提交

1. 勘察战场：查看提交历史与分支

  • git log --oneline --all --graph
    • 作用：以简洁的方式查看所有分支的提交历史图谱。
    • CTF用途：快速发现出题人留下的“作案痕迹”，例如测试性提交、临时回滚、在dev或flag等非主流分支上的可疑提交。
  • git branch -a
    • 作用：列出所有（包括远程）分支。
    • CTF用途：直接找到隐藏的分支名称。Flag有时就在flag、secret这类分支上。

2. 深入分析：查看提交详情与差异

git reset切换版本

  • git show <commit_id>
    • 作用：显示某次提交的详细信息，包括修改的文件和具体的代码差异（diff）。
    • CTF用途：仔细查看某次可疑提交究竟改了什么东西。Flag可能以注释、调试信息、硬编码密码的形式在修改中被添加或删除。
  • git diff <commit_id_A> <commit_id_B>
    • 作用：直接比较两次提交之间的差异。
    • CTF用途：专注于出题人可能刻意隐藏的变化，比如比较最初提交和最新提交，看看哪些“提示”被删除了。

3. 挖掘宝藏：找回丢失的文件与对象
这是CTF中极为常见和重要的一步。

  • git fsck --lost-found
    • 作用：检查仓库的完整性，并列出所有“悬空对象”（即不在任何提交历史中的对象，如被删除分支上的提交、被git rm删除后又commit的文件内容）。
    • CTF用例：执行此命令后，如果输出dangling blob <object_id>，那么恭喜，很可能找到了被删除的flag文件。
  • git show <dangling_blob_object_id>
    • 作用：直接查看这个悬空对象的内容。
    • CTF用例：查看被删除flag文件的内容。有时需要尝试多个object_id。

4. 检查特殊状态与配置文件

  • 检查是否处于“分离头指针”状态：git status
    • 有时出题人可能会让仓库处于一个特殊的临时状态，这里可能有线索。
  • 检查.git目录本身：cat .git/config 或 find .git -type f
    • .git/config 文件中有时会包含敏感路径或服务器信息。
    • .git目录下有时会藏有额外的笔记或flag文件。

💎 高效技巧总结

  • 组合拳：不要只运行一个命令。git log -> git show -> git diff -> git fsck 是一个完整的侦查链条。
  • 关键字搜索：在所有检出文件和历史记录中搜索flag、key、pass、secret等关键字：grep -r "flag{" . 2>/dev/null。
  • 理解出题意图：.git泄露题目的核心是考察“信息残留在版本控制中”。思考出题人可能在哪里“不小心”留下了flag。
