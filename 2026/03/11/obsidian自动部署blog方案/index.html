obsidian自动部署blog

一、方案核心原理

首先理清 Hexo 博客的双仓库逻辑，这是避免后续踩坑的关键：

  1. 源文件仓库（hexo-blog-source）：存放 Hexo 的核心配置、主题文件、文章源文件（.md格式），也是 Obsidian 编辑文章的本地目录，所有写作操作都围绕这个仓库展开。
  2. 页面展示仓库（MetalSO.github.io）：Hexo 自动生成的静态网页文件专属仓库，无需手动操作，由 Hexo 部署命令自动推送更新，最终通过 GitHub Pages 展示博客。

我们的目标：Obsidian 写完文章→自动同步源文件到 GitHub 源仓库→一键 / 自动执行 Hexo 部署→网页仓库更新→博客实时发布，实现「写完即上线」的自动化流程。

二、前期准备

  1. 已搭建好 Hexo 博客，本地博客根目录为soblog（核心路径：C:\Users\Administrator\soblog），且拥有上述两个 GitHub 仓库；
  2. 本地安装 Git，完成 GitHub 账号的基础配置；
  3. Obsidian 已安装Git 插件，这是实现自动同步的核心工具；
  4. 确认本地博客文章统一存放在soblog/source/_posts/路径下（Hexo 默认文章目录，只有放在这里才能被识别生成博客页面）。

（二）Obsidian Git 插件自动同步配置

这是实现「Obsidian 写完自动传 GitHub」的核心，无需手动敲 Git 命令，插件全程代劳：

  1. 打开 Obsidian→左下角设置→找到已安装的 Git 插件，进入配置页面；
  2. 开启自动提交：找到Auto commit-and-sync after stopping file edits，打开开关，设置提交间隔为 5 分钟（停止编辑文章 5 分钟后自动提交本地修改）；
  3. 开启自动推送：找到Auto push interval (minutes)，将数值改为 1-5 分钟（提交后自动推送到 GitHub 源仓库，别设为 0，否则不推送）；
  4. 绑定分支：在插件顶部Branch选项中填写main，与远程分支保持一致。

配置完成后，只要在 Obsidian 里编辑source/_posts下的文章，保存并停止编辑后，插件会自动完成「提交 + 推送」，无需任何手动操作。

四、完整自动化流程

配置完成后，后续发布博客只需三步，全程极简：

  1. 写文章：在 Obsidian 中新建.md文件，保存至soblog/source/_posts/目录，正常编辑内容；
  2. 等同步：停止编辑文章后，等待 5-10 分钟，Obsidian Git 自动将文章同步到 GitHub 源仓库；
  3. 触发部署：本地终端执行hexo g -d，或配置自动化脚本实现一键部署，Hexo 自动生成网页并更新线上博客。

五、常见问题避坑

  1. 推送报错 502：GitHub 服务器临时故障，等待 5-10 分钟重试即可，无需修改本地配置；
  2. 自动同步不生效：检查 Obsidian Git 插件的自动推送间隔是否为 0、文章是否存放在source/_posts、分支是否绑定为 main；
  3. 博客未更新：确认执行了hexo g -d部署命令，检查页面展示仓库是否有新的静态文件，GitHub Pages 部署需 1-2 分钟延迟。

六、总结

这套 Obsidian+Hexo 自动化部署方案，彻底解决了「手动写命令、手动传文件、手动部署」的繁琐流程，把精力完全放在内容创作上。只要做好前期的仓库和插件配置，就能实现「Obsidian 写完文章，自动同步 + 自动部署上线」，对于喜欢用 Obsidian 写作的 Hexo 博主来说，实用性拉满，再也不用为部署博客浪费时间啦！
